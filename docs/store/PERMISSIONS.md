# Permissions: what each is for (store review, 2026-11-18)

| Permission | Why | Narrowed to |
|---|---|---|
| `host_permissions: http://*/*, https://*/*` | (1) The in-page buttons run on the pages the person browses, in their frames too. (2) A `.torrent`, `.nzb`, `.meta4` or newznab indexer link is captured by a background fetch with the person's existing session on the site serving it (spike S1); that site is any site. (3) The DownloadPulse on this computer (`127.0.0.1`/`localhost:8095`), or the server the person names, is reached from the background. | Web pages only (`<all_urls>` dropped): no `file:`, `ftp:` or other schemes. |
| `content_scripts` on `http://*/*`, `https://*/*`, `all_frames: true` | The hover, video and selection buttons. Frames: video players and download links are often in embedded frames (YouTube embeds; spike S3). The script reads no storage and holds no secret; it asks the background what it may offer. It can be switched off globally or per site. | Web pages only. |
| `storage` | The connection's details, settings, the disclosure agreement and the theme (see PRIVACY.md). The connection key itself is in the extension origin's IndexedDB. | — |
| `contextMenus` | "Download with DownloadPulse" on links and selected text, shown only while connected. | — |
| `notifications` | Finished, failed and needs-attention notices, each switchable. | — |
| `dns` (Firefox only) | Whether a server or file-link name that looks like an internet name resolves only to private addresses (split DNS, e.g. `nas.home.example.com`), so plain HTTP may be allowed there after the warning screen. The browser's own resolver; no lookup leaves the system's usual DNS path. | Read only: resolves a name the person entered, or a file link they sent. |
| `cookies` | A video the person sends goes with their sign-in on its site: the cookies the browser would send to the video's own address (for an embed, the player's address, with its partitioned cookies under the page's site), from the tab's own cookie store (a Firefox container's). Only for a video send, only to a DownloadPulse whose session says it accepts them, and only over HTTPS or to DownloadPulse on this computer (never over plain HTTP); on by default, switchable ("Send my sign-in on the site with videos and browser downloads"). 1.0.2: also a browser download sent to DownloadPulse (opt-in, above), with the cookies for that download's own address from its own cookie store, under the same transport rule and (1.0.4) the same switch. A browser download whose sign-in does not go is left to the browser to finish. | Read only, never set or removed; never for links, files or selections sent by hand; never kept by the extension. |
| `optional_permissions: downloads` (1.0.2) | Browser downloads sent to DownloadPulse instead: the extension sees a download the browser starts (`downloads.onCreated`), pauses it while DownloadPulse downloads it, and cancels and erases the browser's copy only once DownloadPulse has finished it (1.0.3), else resumes it. A download the browser cannot pause is cancelled once DownloadPulse accepts it. Asked for only from the person's own click (the setup offer after connecting, or the switch in the popup or Settings); turning it off removes the permission. | Optional: never requested on install or update. Not for `blob:`/`data:`/`file:` downloads, another extension's, `.torrent`/`.nzb`/`.meta4`, files under the person's minimum size or of a type they listed. |
| `alarms` | Wakes the monitor of unsettled downloads (MV3 background lifetime). | — |
| `incognito: not_allowed` | Never in private windows: a private session's downloads would enter DownloadPulse's lasting queue. | — |

**Why not request site access at use:** the in-page buttons must be present on a page before the person acts there, which makes runtime grants impractical for that feature. Capture needs the serving site's origin at the moment of the click, from the background (a context-menu click or an in-page button), where Chromium cannot always show a permission prompt.

**Code:** all executable code ships in the package. It's bundled with esbuild, with no remote code, `eval` or remote fonts (Outfit is bundled under OFL-1.1).
