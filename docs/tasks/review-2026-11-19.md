# External review of 29cf776 (2026-11-19)

An outside review of the whole extension. Every claim was checked against the code. The operator decided the policy items.

## Fixed

1. **A stray `%` in a URL threw** (`/50%off/file.torrent`). `captureKind` and `isDownloadCandidate` now read such a path as written (`decodedPath`).
2. **Duplicates:**
   - **Timeouts:** a send that times out or loses its connection is retried once with the same key, so DownloadPulse answers the same job.
   - **Repeats:** a repeat of the same send (same server, same link or file) within 10 minutes reuses its key (operator). DownloadPulse answers the same job, never a second one. A selection retried after a partial failure reuses each item's key the same way.
   - **Stored:** for the browser session only, a SHA-256 of server and source, never the link.
   - **Removed downloads:** removing one in the extension forgets its key, so sending it again is a new request.
3. **Uploads:** a submission carrying a captured file gets 120 s, not 8 s.
4. **Capture cap:** the body is read as it arrives and stopped past the cap (`bounded`). A file with no length is never buffered whole first, and a timeout mid-read is a capture failure, not a generic one.
5. **Loopback:** all of 127.0.0.0/8 is this computer.
6. **Tailscale** (operator): 100.64.0.0/10 and `*.ts.net` count as the private network. Plain HTTP is allowed there after the warning screen.
7. **Split DNS** (operator):
   - **Firefox:** a name resolving only to private addresses counts as the private network (the new Firefox-only `dns` permission; `effectiveAddress`, `resolvesPrivate`). It applies to connecting, the saved-connection gate, the request helper's guard and captures.
   - **Chromium:** it has no DNS API for extensions, so such names stay HTTPS-only there.
8. **Something in front of DownloadPulse:**
   - **The case:** a redirect, or a 401/403/407 from DownloadPulse's always-public health check.
   - **The message:** it is now said plainly (`failureBlocked`) instead of "unreachable" or "certificate".
   - **Redirects:** the request helper follows none (`redirect: "manual"`).
9. **Monitor:**
   - the wake-up alarm is set or cleared when that changes, not on every 125 ms pass;
   - the loop runs frames only while the icon breathes, and otherwise wakes at the polling pace.
10. **Sends:**
    - only `http(s)` and `magnet:` links are sent;
    - a selection with more than 100 plain links sends the first 100 and says so (`sendSelectionCapped`).

## Not changed

- **"Dead permission code":** not dead. Firefox lets the person withhold host access, and Chromium lets them limit it per site, so `permissions.request` and `permissions.contains` can fail.
- **Pointer tracking cost:** coalesced to one pass per frame; not measured.
- **Reverse proxies with sign-in:** the extension sends no cookies (by design, PRIVACY.md). Such a gate is now named, not passed.

## Proof

- **Unit tests:**
  - `%` paths;
  - 127/8;
  - Tailscale addresses and names, and their neighbours not counted.
- **e2e:**
  - a timed-out first send is retried as the same job, and a repeat send is the same job;
  - an endless file is refused at the cap within seconds;
  - 101 selected links send 100;
  - a proxy in front is named.
- **Mutation checks:** the streamed cap, key reuse, the timeout retry and the proxy message each fail their test without the fix.
- **Not proven:**
  - the capped toast's words: its shadow root is closed, so the test sees only that a toast appears;
  - Firefox's DNS lookup in a real split-DNS network.

**Strings:** two new, in 18 locales, reviewed; none corrected.
